Дата тестирования: 2026-06-18

## Критические — исправлены в этой сессии

### BUG-01 · Главная страница крашила из-за `http://` URL в `next/image`
**Страница:** `/`  
**Статус:** ✅ Исправлено  
**Описание:** API возвращает медиа-URL вида `http://imbir.sino0on.ru/...`, а `next.config.ts` разрешает только `https://`. Это вызывало runtime-ошибку Next.js и полный краш главной страницы.  
**Фикс:** Добавлен хелпер `toHttps()` в `src/shared/api/requests.ts`, нормализующий протокол для всех URL от `imbir.sino0on.ru` (применён в `adaptClinic` и `adaptDoctor`).

## Высокий приоритет — исправлены в этой сессии

### BUG-02 · Кнопки записи на специалисте не работали
**Страницы:** `/specialists/[id]`  
**Статус:** ✅ Исправлено  
**Описание:** Кнопки «Офлайн-запись» и «Видео-консультация» (и мобильные аналоги «Офлайн» / «Онлайн») не имели обработчиков — клик ничего не делал.  
**Фикс:** `src/views/specialist-details/ui.tsx` — добавлены `onClick` с навигацией на `/record?doctor={id}&mode=offline|online`.

### BUG-03 · Кнопки записи на странице клиники не работали
**Страницы:** `/clinics/[id]`  
**Статус:** ✅ Исправлено  
**Описание:** Кнопки «Офлайн-консультация» и «Онлайн-консультация» не имели обработчиков.  
**Фикс:** `src/views/clinic-details/ui.tsx` — добавлены `onClick` с навигацией на `/record?clinic={id}&mode=offline|online`.

### BUG-04 · Страница записи не подхватывала контекст из URL
**Страницы:** `/record?doctor=X&clinic=Y&mode=Z`  
**Статус:** ✅ Исправлено  
**Описание:** После фиксов BUG-02/03 при переходе с карточки специалиста/клиники на `/record` поля «Специалист», «Клиника» и режим оставались пустыми — URL-параметры игнорировались.  
**Фикс:** `src/views/record/ui.tsx` — расширен `useEffect` для чтения `?doctor=`, `?clinic=` и `?mode=` из URL при монтировании.

### BUG-05 · Несуществующий ID специалиста давал бесконечный спиннер
**Страницы:** `/specialists/[несуществующий-id]`  
**Статус:** ✅ Исправлено  
**Описание:** При запросе несуществующего врача запрос возвращал `null` или ошибку, но страница показывала «Загрузка специалиста...» вечно.  
**Фикс:** `src/views/specialist-details/ui.tsx` — разделены состояния `isError` и `!doctor` (показывает «Специалист не найден» со ссылкой назад) и `isLoading` (показывает спиннер только пока идёт запрос).

### BUG-06 · Несуществующий ID клиники давал бесконечный спиннер
**Страницы:** `/clinics/[несуществующий-id]`  
**Статус:** ✅ Исправлено  
**Описание:** Аналогично BUG-05, только для клиник.  
**Фикс:** `src/views/clinic-details/ui.tsx` — та же схема: «Клиника не найдена» + ссылка назад.

## Высокий приоритет — не исправлены (данные бэкенда / требуют обсуждения)

### BUG-07 · Все клиники показывают одинаковое неправильное лого
**Страницы:** `/`, `/clinics`, `/clinics/[id]`  
**Статус:** ✅ Частично исправлено (фронтенд)  
**Описание:** Все клиники в базе данных используют логотип «Nova Aesthetics» — тестовые данные на бэкенде. Фронтенд теперь показывает стилизованный fallback с аббревиатурой и названием клиники в цветах сайта, когда изображение отсутствует или не загружается.  
**Фикс:** `src/entities/clinic/ui.tsx` — добавлен компонент `ClinicImageFallback` (градиент `#FFF2F0→#FFD9CC`, аббревиатура в оранжевом квадрате, название клиники), состояние `imageError` и `onError` на `<Image>` в обоих вариантах карточки (horizontal/vertical).  
**Осталось:** Загрузить реальные логотипы на бэкенде.

### BUG-08 · На странице клиники отсутствует список врачей
**Страницы:** `/clinics/[id]`  
**Статус:** ⚠️ Не исправлено  
**Описание:** Клиники имеют связанных врачей в API (12 и 25 соответственно), но секция «Специалисты» на детальной странице клиники отсутствует или не отображает эти данные.  
**Предложение:** Добавить секцию специалистов на страницу клиники, используя `api.getDoctors()` с фильтрацией по clinic ID.

### BUG-09 · Все услуги показывают «Клиника не указана» и нулевой рейтинг
**Страницы:** `/services`  
**Статус:** ⚠️ Не исправлено  
**Описание:** Все карточки услуг показывают «Клиника не указана», `0` рейтинг и плейсхолдер-аватары вместо изображений. Данные в базе неполны.  
**Предложение:** Проверить данные на бэкенде; добавить fallback-текст «Изображение отсутствует» в карточке услуги.
