# Регистрация врача и специализации — 2026-10-03

## Изменения

- Формы регистрации и редактирования врача/клиники используют полный справочник
  `GET /api/references/specializations/?include_unused=true`. Каталоги и их фильтры
  по-прежнему используют только направления опубликованных профилей.
- Врачебные формы показывают запрошенные названия (Кардиолог, Эндокринолог,
  Ревматолог, Ортопед, Гастроэнтеролог, Флеболог, Уролог, Маммолог, Фиброскан,
  Лор, Окулист, Хирург, Дерматолог, Гепатолог), сохраняя существующие ID.
- В `step5` регистрации врача исправлены поля на `primary_specializations` и
  `narrow_specializations`: именно их принимает регистрационный API. Профильный
  PUT продолжает использовать свои поля с суффиксом `_ids`.
- Исправление блокировки регистрации долгой обработкой фото уже находится в
  исходном master (`47a738f`): аккаунт создаётся без фото, фото загружается отдельно.
  Это не новое изменение этой ветки. По одному пользовательскому скриншоту
  невозможно доказать, какой именно HTTP-запрос завершился ошибкой.

## Проверено

- Бэкенд: 7 тестов прошли. Проверены полный справочник, прежняя фильтрация,
  повторное заполнение справочника без дубликатов, регистрация с подтверждённым
  телефоном и сохранением специализации, отказ без подтверждения контакта.
  Тесты запускались в изолированной SQLite `:memory:` внутри контейнера с
  зависимостями проекта; настоящая база не изменялась.
- Браузер Chrome, мобильный размер 390×844: все 14 названий присутствуют в
  списке. Пройден путь выбора Флеболога, подтверждения телефона и открытия
  кабинета врача. Использован локальный API-стенд с синтетическими данными,
  без настоящего SMS и без создания аккаунта в проде. Стенд подтвердил передачу
  ID специализации в регистрационном запросе и отсутствие фото в нём.
- `npx tsc --noEmit`, ESLint изменённых TS/TSX и `npm run build` — успешно.
  Сборка использовала локальный API-стенд. Остались существующие предупреждения
  об устаревшем Browserslist и соглашении middleware, не ошибки сборки.
- Read-only проверка продовой базы: все 14 направлений уже существуют под
  соответствующими названиями/вариантами; публичный справочник отдавал только 3.

## Выпуск

Прод не обновлялся. Сначала требуется выпустить изменение бэкенда
`include_unused`, затем фронтенд. Миграции не нужны. Для другой/пустой базы
есть идемпотентная команда `python manage.py seed_registration_specializations`;
в проверенной продовой базе недостающих направлений нет.

После выпуска проверить реальный GET полного справочника и регистрацию на
телефоне. Текущая браузерная проверка — не замена тесту iOS Safari на проде.
