## 1. Подключить e2e-тесты авторизации — отложено 2026-08-11

**Статус:** скрипт написан, работает, лежит в репозитории, но НИ К ЧЕМУ НЕ ПОДКЛЮЧЁН.

**Что уже есть:** [`e2e/auth.e2e.mjs`](../e2e/auth.e2e.mjs) — 25 проверок, все проходят.
Запуск (нужен поднятый dev-сервер на `localhost:3001`):

```bash
npm run dev          # в одном терминале
node e2e/auth.e2e.mjs  # в другом
```

Покрывает:
- `/login` грузится без JS-ошибок и без перезагрузок (ровно 1 запрос документа)
- Enter отправляет форму логина, не перезагружает страницу, доводит до `/profile/my-data`
- клик по кнопке эквивалентен Enter
- Tab доходит от почты до «Продолжить», у кнопки видно кольцо фокуса
- «Показать пароль» раскрывает пароль и НЕ сабмитит форму
- регистрация пациента: Enter проводит роль → шаг 1 → шаг 2 → создание аккаунта
- регистрация клиники: Enter не «проваливает» шаги
- чат: «Перейти в чат» и «Описать симптомы» открывают ИИ-помощника, симптом уходит в `/api/chat/ai/send/`
- кривой `recommendations` с бэка не роняет чат в error boundary

**Что осталось сделать:**
- решить формат: оставить как есть (голый node-скрипт) или перевести на `@playwright/test` с раннером, репортом и ретраями
- добавить скрипт в `package.json` (`"e2e": "node e2e/auth.e2e.mjs"`), сейчас его там нет
- поднимать dev-сервер автоматически (`webServer` в конфиге playwright), сейчас нужен вручную
- решить, гонять ли в CI

**Зачем:** тестов в проекте нет вообще ([QUESTIONS.md №13](./QUESTIONS.md)). Этот набор ловит ровно тот класс регрессий, который уже случался: сломанная отправка форм и упавшая авторизация.

**Связанное решение:** `playwright` добавлен в `devDependencies` (`package.json`). Если тесты не подключаем — зависимость и папку `e2e/` надо убрать.

## 2. Сохранять `?ask` при входе в чат неавторизованным — отложено 2026-08-11

Сейчас: гость открывает `/chat?ask=<симптом>` → видит «Войдите, чтобы открыть чаты» → жмёт «Войти» → после логина попадает на `/profile`. Вопрос, который он набрал на главной, теряется.

Где смотреть: `LoginPrompt` в [`src/pages/chat/ui.tsx`](../src/pages/chat/ui.tsx), редирект по роли в [`src/pages/login/ui.tsx`](../src/pages/login/ui.tsx).

Варианты: прокинуть `?next=/chat?ask=...` в ссылку на логин и учесть его в редиректе после входа; либо сохранять симптом в стор и подхватывать после авторизации.

## 3. «Глаз» показа пароля в таб-порядке — нужно решение — отложено 2026-08-11

Сейчас кнопка «Показать пароль» — полноценный `<button>` с `aria-label`, то есть **занимает отдельный таб-стоп** между полями: `пароль → глаз → следующее поле`. Так делают GitHub и Google, и без этого пароль нельзя показать с клавиатуры вообще.

Если нужен «чистый» проход по инпутам — добавить `tabIndex={-1}` кнопке в [`src/shared/ui/input/ui.tsx`](../src/shared/ui/input/ui.tsx). Это одна строка, но теряется клавиатурная доступность.

## 4. Проверить кнопку «Написать» у врача — отложено 2026-08-11

[`src/features/start-chat/ui.tsx:42`](../src/features/start-chat/ui.tsx) уводит на `/chat?room=<id>`. Этот параметр читался тем же сломанным механизмом, что и `?ask` (императивное чтение `window.location` в инициализаторе `useState` — см. [BUGS.md](./BUGS.md) и правку в `src/pages/chat/ui.tsx`), поэтому кнопка, скорее всего, тоже не работала.

Механизм починен и `?room=` теперь читается через `useSearchParams`, но **живьём с реальной комнатой я это не проверял** — в e2e-скрипте покрыт только ИИ-чат. Нужен прогон на странице реального врача.

## Правило работы, выясненное дорогой ценой

**Не запускать `npm run build`, пока поднят `npm run dev`.** Они делят каталог `.next`; прод-сборка переписывает манифесты под живым dev-сервером, Turbopack теряет состояние проекта и падает с `Next.js package not found`, а страница уходит в цикл перезагрузки. Лечится `rm -rf .next` и рестартом dev.

Для проверок при живом dev-сервере годятся `npx tsc --noEmit` и `npx eslint` — они в `.next` не пишут.
